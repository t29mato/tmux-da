# tmux からくり屋敷（tmux-yashiki）

tmux のキーで屋敷の仕掛けを解くタイムアタック。襖を立て（分割）、間を渡り（移動）、大広間にし（全画面）、棟を建て（ウィンドウ）、巻物を読む（コピーモード）。押すキーはいつも画面の「指図」に出ているので、遊んでいるうちに指が覚える。

**▶ 今すぐ遊ぶ: https://t29mato.github.io/games/tmux-yashiki/**

- **ブラウザ版（`web/`）**: 3 つの屋敷のタイムアタック。インストール不要。番付（ランキング）と端末の引き継ぎは任意
- **CLI 版（`./tmux-da`）**: 本物の tmux の中で 11 面を解く

## ブラウザ版（`web/`）

ページの中の小さな tmux で遊ぶ。`web/index.html` をそのまま開けば動く（`file://` でも静的サーバーでも）。名前か合言葉を付けるまでは一切通信しない。

| 屋敷 | 仕掛け | 目安 | 中身 |
|---|---|---|---|
| 三間屋敷（手ならし・初めてはここ） | 15 | 12 秒 | 分割・移動・全画面・閉じる・ウィンドウの作成と切り替え。1 仕掛け 1 キー |
| 八間屋敷（腕試し） | 20 | 14 秒 | 大きさ・名前・入れ替え・ウィンドウを閉じる・スクロール（コピーモード）も混ざる |
| 百間屋敷（真剣勝負） | 16 | 18 秒 | 1 仕掛けで 2〜3 手の連続技 |

- 仕掛けの組は毎回同じで、順番だけが毎回ちがう。全部解くまでの時間を競う。違う操作は +2 秒（仕掛け違い）
- **屋敷はつながっている**: 1 回の挑戦は 1 つの tmux セッションの上で進む。解いた仕掛けのあとも、ペイン・ウィンドウ・全画面・いま居る場所はそのまま残り、次の仕掛けはその場所から出る（「今どこ？」から始まらない）。屋敷の最初の形は全員同じ（母屋に 3 ペイン、離れと蔵に 2 ペイン、母屋から始まる）。仕掛けに足りないもの（2 つ目のペインや別のウィンドウ、全画面の解除）があるときだけ屋敷が最小限で補い、指図の下に「ペインを 1 つ足した」のように一言出る。居場所は変えない。`z` の「戻す」は「全画面にする」の直後に出る
- **指図は平文**: やることは「左右に分割する（split）」「『座敷』へ移動する」「ウィンドウ 2:蔵 を閉じる」のように、動作を先に、tmux の言葉を添えて書く。部屋の名前（茶の間・座敷……）は札として残る
- **時間切れで飛ばさない**: 1 問は解けるまで終わらない。指図には答えの手順（指南）と押すキーがいつも出ている。目安を過ぎると行灯がともるが、先には進まない。タブを離れると自動で一時停止
- 結果は「絵巻」に残る。自己ベスト、五回平均、目標タイム（当主の刻）との差、称号（見習い → 仕掛け番 → 屋敷守 → からくり師 → 名匠）、遅れた仕掛け
- 「絵巻」の画面で、屋敷ごとのタイムの移り変わりと、灯りが多い（苦手な）仕掛けとそのキーが見られる
- **素の tmux の画面**: 遊ぶ画面は本物の tmux と同じ見た目（黒い端末、緑のステータスバー）。ペインは名前ではなく `prefix q` と同じ番号で示し、いま居るペインは緑の枠と番号。やることと次のキーは、いま居るペインのプロンプトのすぐ上にシェルのコメント（`#`）として出る。行き先のペインには点線と印、いま居るペインからの矢印（押すキーつき）
- **覚えた仕掛け**: 目安以内・ミスなしで 3 回続けて解いた仕掛けは、指南を畳む（目安を過ぎたら開く）。覚えるまで答えを読むだけにならないように
- **腕前**: 直近 5 回のペースから Lv.1〜30 と称号を出す。次の Lv まで 1 仕掛けあたり何秒速くすればよいかも出る
- **稽古の間**: 苦手な仕掛け 3 種だけを 3 回ずつ。番付には載らない
- **今日の屋敷**: 出題の順番は、その日（日本時間）は全員同じ。番付が運に左右されない。仕掛けが狙うペインやウィンドウは、その順番と、そのとき屋敷にある部屋から同じ乱数で選ぶ
- **キーボードだけで回る**: 見取り図で Enter（1〜3 で屋敷を選ぶ、K で稽古、R で絵巻）、結果で Enter もう一度、Esc で戻る
- **成**: 解いた仕掛けは「成」の印の下で部屋の動きを見せてから次へ（0.65 秒、時計は止まる。キーを押せばすぐ次へ）
- **隣のペインへの移り方**: 本物の tmux と同じく、端で押すと反対側のペインへ回り込み、全画面中に押すと全画面を解いて移る。指南は矢印に加えて別解（`o` で次のペインへ、`;` で直前のペインへ）も出す
- **自分の .tmux.conf**: 見取り図の「キー設定」に貼ると、その合図とキーで遊べ、指南もそのキーで出る。読めるのは `set -g prefix`、ゲームにある操作への `bind` / `bind -n` / `bind -r` / `unbind`、vim-tmux-navigator（プラグインの既定どおり `Ctrl+h/j/k/l`、`Ctrl+\`、合図 → `Ctrl+l`）。読めない行は理由つきで一覧に出す。自分の設定で遊んだ記録も、既定のキーの記録と同じ番付に載る
- **静かな屋敷**: 右上の「静」で、振り子・湯気・灯などずっと動く飾りを止める（初めは止まっている）
- **影（ゴースト）**: 自分のベストか、今日の一番の走りと競う。1 仕掛け解くたびに、影より何秒前か後ろかが出る
- **番付**: 名前を付けると、遊ぶたびに今日・今週・全期間の番付に載る（ログイン不要）
- **引き継ぎ**: 「絵巻 → 引き継ぎ」に出る合言葉（例: `matsu-kaze-tsuru-482`）を別の端末で入れると、同じ記録が見られる
- 音は Web Audio で鳴らす（琴・拍子木・鈴。音のファイルは読み込まない）。右上の ♪ で消せる

```bash
open web/index.html                      # macOS
python3 -m http.server -d web 8000       # または http://localhost:8000/
```

- 合図（prefix）は tmux 標準の Ctrl+b。記録と設定は localStorage に残る（無くても動く）
- Mac で Ctrl+矢印が Mission Control に取られるときは、prefix のあと Option+矢印でも大きさを変えられる
- 狭い画面では画面下にキーの列が出るので、iPhone でも遊べる
- 夜の屋敷（ダーク）／昼の屋敷（ライト）は OS 設定に従い、右上のボタンで切り替えられる

## サーバ（`server/`）

番付と引き継ぎのための小さな API。Cloudflare Workers ＋ D1（SQLite）。アカウントは無く、合言葉は SHA-256 だけを保存する。記録の検証（1 仕掛け 0.25 秒未満や、合計が合わない記録は弾く）と、アドレスごとの回数制限をする。

```bash
cd server
npx wrangler d1 execute tmux-da --remote --file schema.sql   # 表を作る（初回だけ）
npx wrangler deploy
```

## テスト

```bash
npm install          # Playwright と wrangler（初回だけ。npx playwright install chromium も）
npm test             # 全部
npm run test:unit    # 単体テストだけ（数秒）
scripts/test.sh game # unit | game | online | cli のどれか 1 つ
```

| 種類 | 場所 | 中身 |
|---|---|---|
| 単体 | `web/test/unit/` | 屋敷と称号、記録（追加・移行・端末の合流・影・苦手）、通信（偽のサーバ相手） |
| 単体＋API | `server/test/` | 合言葉・記録の検証規則、API 全体を Node 内蔵の SQLite 上で（同期・名前・番付・影・回数制限・CORS） |
| 結合（ゲーム） | `web/test/playthrough.mjs` | 本物のキーボードイベントで 3 つの屋敷を通す。指南だけで全種類解けるか、仕掛けの境で居場所と部屋が引き継がれるか、指図の文字が動かないか、飛ばないか、一時停止、行の編集、音 |
| 結合（通信） | `web/test/online.mjs`, `server/smoke.mjs` | `wrangler dev --local` を立て、ブラウザ 2 つを 2 台の端末に見立てて同期・番付・影を通す |
| CLI 版 | `test/playthrough.sh` | 下を参照 |

push のたびに GitHub Actions（`.github/workflows/test.yml`）で全部が走る。

### CLI 版のテスト

```bash
test/playthrough.sh
```

キー操作の代わりに tmux のコマンドで全面を解き、見張り役が 1 面ずつ進めるかを確かめる。`script(1)` で疑似端末のクライアントをつなぐので、デタッチと再接続の面も試せる。
