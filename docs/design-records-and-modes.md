# tmux打 追加機能 設計書 — 「記録の間」と 3 つの難易度

## 0. 現状の整理（読んで確認したこと）

| 項目 | 現状 | 場所 |
|---|---|---|
| コース | すでに 3 本ある: `easy` 草原コース（15 問・制限 12 秒/問）、`normal` 塔コース（20 問・14 秒）、`hard` 城コース（16 問・18 秒）。問題セットは固定、毎回シャッフル（同じ問題が連続しない） | `web/js/levels.js:366-382`, `app.js:1472-1502` |
| スコア | `time = 実時間 + ペナルティ`（ミス +2 秒、時間切れ +5 秒）。称号は `rankFor(avg)`（1 問あたり秒）で全コース共通のしきい値 | `app.js:1632-1636`, `levels.js:391-402` |
| 保存 | `localStorage['tmux-da']` = `{ prefix, level, theme, sound, arena: { 'tmux:easy': { time, misses, date:'YYYY-MM-DD' } } }`。**自己ベスト 1 件しか残らない**。新記録のときだけ上書き | `app.js:20-43`, `app.js:1637-1645` |
| 記録の消去 | `store.clear()` は `arena` だけ残す（「記録を消す」は冒険の話） | `app.js:35-42` |
| 結果画面 | `#arena-result` に タイム・称号・1 問あたり・実時間・ミス・時間切れ・押したキー・これまでの最高・豆知識・もう一度 | `app.js:2285-2321` |
| 問ごとの計測 | `b.qStart` はあるが**問ごとの所要時間・ミスは記録されていない**（ダメージ計算に使うだけ） | `app.js:1552-1583` |
| テスト API | `window.tmuxDa.state()` に `result`, `battle` など。テストは `.course-best` のテキストと `result.record` を見ている | `app.js:2435-2460`, `test/playthrough.mjs:500-542` |

結論: 「3 モード」は骨格としては既にあるので、**置き換えではなく、寿司打のように性格づけを明確にして磨く**。履歴は**保存層がベスト 1 件しか持っていない**のが根本なので、ここを「全プレイを残す」に変えるのが本丸。

## 1. 3 モードの設計

### 1.1 方針

- **コース ID（`easy` / `normal` / `hard`）と問題セットは変えない。** 既存記録 `tmux:<id>` との互換を保ち、過去の自分と比べられることが「成長を見る」の前提になるため。
- 寿司打の「お手軽・お勧め・高級」に相当する**モード名を添え、「おすすめ」バッジで normal を標準に据える**。
- 寿司打の「元を取る」に相当する**目標タイム（par）**を各モードに置く。結果画面で「目標まであと X 秒 / 目標達成！」が出る。
- 称号のしきい値を**コースごとに係数で補正**する。いまは城コース（1 問 2〜3 手）で「伝説の勇者」が実質取れない。

### 1.2 モード定義

| id | 表示名 | モード名（寿司打対応） | 出題範囲 | 問数 / 制限 | 称号係数 `rankMul` | 目標タイム par | 狙い・対象 |
|---|---|---|---|---|---|---|---|
| `easy` | 草原コース | **手ならし**（お手軽） | 第 1 章の呪文: 分割・移動・全画面・閉じる・部屋 | 15 問 / 12 秒 | 1.0 | 15 × 2.4 × 1.0 = **36 秒** | 初めての人、冒険第 1 章を終えた直後。1 問 1 キーで「指が動く」体験を作る |
| `normal` | 塔コース | **おすすめ**（お勧め）★デフォルト | 第 1〜2 章: + 大きさ・名前・入れ替え・部屋ごと閉じる・コピーモード | 20 問 / 14 秒 | 1.3 | 20 × 2.4 × 1.3 ≈ **62 秒** | 日常で tmux を使う人の標準コース。日々の記録を積む場所 |
| `hard` | 城コース | **真剣勝負**（高級） | 連続技（探して全画面・三叉・2 匹退治・作って戻る・運んで全画面） | 16 問 / 18 秒 | 2.0 | 16 × 2.4 × 2.0 ≈ **77 秒** | 手順を考えずに連打できるか。冒険第 3 章クリア者向け |

命名の代案（どれか 1 系統で統一する。推奨は上の「手ならし／おすすめ／真剣勝負」= 寿司打の軽さに近く、称号名の「勇者」系と衝突しない）:
- DQ 風難易度: 「らくらく／ふつう／いばらの道」
- モンスター級: 「プルプル級／ヤミコウモリ級／カゲナイト級」（モンスター名 `MONSTERS` を流用）

### 1.3 スコア計算（変更点だけ）

- `time`（= 実時間 + ペナルティ）が引き続き**唯一の記録**。小さいほど良い。
- 称号: `rankFor(avg / course.rankMul)`。`levels.js` の `RANKS` はそのまま、`rankFor(avg, mul)` に第 2 引数を足す。
- 目標タイム: `par(course) = course.qs.length * RANKS[1].max('勇者' = 2.4) * course.rankMul`。保存しない（導出値）。
- **問ごとの秒数**を新たに記録する（1.4 参照）。スコアには影響しない。

### 1.4 `levels.js` への追加

```js
// COURSES の各要素に追加
{ id: 'normal', title: '塔コース', mode: 'おすすめ', sub: '中級', recommended: true,
  rankMul: 1.3, ver: 1, /* 既存: monster, limit, desc, qs */ }
```

- `ver`: 問題セット（`qs`）や `limit` を**変えたら +1**。履歴は `ver` を持つので、将来セットを変えても旧記録を「旧コース」として分けて見せられる。今回は全部 `1`。
- `rankFor(avg, mul)` と `par(course)` を `window.ADV.levels` に追加。

### 1.5 検討して採らなかったこと

- **寿司打方式（制限時間固定・解いた数を競う）への転換**: 記録が「秒」から「問数」に変わり既存記録が比較不能になる。問題セット固定で「同じ試験を受け直す」構造のほうが成長が見えるので採らない。
- **難しいモードではヒントを消す**: 「キーとヒントは常に表示」の方針に反する。難度は手数と制限時間で付ける。

## 2. 記録履歴: データ設計

### 2.1 新ファイル `web/js/records.js`

DOM を触らない純粋なモジュールを 1 つ足し、`window.ADV.records` として公開。`app.js`（106KB）を太らせず、あとでシェアカードがそのまま使える。`index.html` では `levels.js` の次、`app.js` の前に読み込む。

```
ADV.records = {
  SCHEMA: 2, CAP: 100, HARD_CAP: 200,
  load(),                     // {schema, arena, runs} を正規化して返す（移行込み）
  add(run),                   // 1 プレイ追加・ベスト更新・間引き・保存。戻り値は summary
  runsOf(courseId, {ver}),    // 新しい順の配列
  best(courseId),             // arena['tmux:<id>'] 相当
  summarize(courseId, run),   // 結果画面用: prev, delta, bestDelta, count, rankUp, par, spark
  stats(courseId),            // 記録の間用: best, count, first, last, recent5avg, series
  weakness(courseId, n=10),   // 苦手分析: [{type, avg, missRate, timeouts, ratio}]
  clearArena()                // 闘技場の記録だけ全消去
}
```

保存は既存 `store`（`'tmux-da'` キー）に**同居**させる。理由: 1 キーで完結し `store.clear()` の「arena を残す」を `runs` にも広げるだけで済む。

### 2.2 localStorage スキーマ（`'tmux-da'`）

```jsonc
{
  "schema": 2,
  "prefix": "C-b", "level": 12, "theme": "dark", "sound": true,   // 既存どおり

  // 既存: 自己ベストのキャッシュ。キー名 'tmux:<course>' は変えない（テスト・互換）
  "arena": {
    "tmux:easy": { "time": 28.4, "misses": 1, "date": "2026-10-20", "runId": "r_k3x9…", "ver": 1 }
  },

  // 新規: 全プレイ。新しいものを末尾に push
  "runs": [
    {
      "id": "r_k3x9a1",            // Date.now().toString(36) + 乱数 2 桁。シェアカードの参照用
      "course": "easy", "ver": 1,
      "at": "2026-10-20T10:31:04.120Z",   // ISO 8601 UTC。表示は new Date(at) でローカル化
      "prefix": "C-b",
      "time": 28.4, "raw": 24.4, "misses": 1, "timeouts": 0, "keys": 23, "n": 15,
      "rank": "勇者",              // その時点の称号（しきい値を後で変えても当時の値が残る）
      "rec": true,                 // 新記録だったか
      "qs": [                      // 出題順の問ごとのログ。苦手分析の材料
        { "t": "split_lr", "s": 1.2, "m": 0 },
        { "t": "focus",    "s": 3.8, "m": 1 },
        { "t": "copy_top", "s": null, "m": 0, "to": 1 }   // 時間切れは s: null, to: 1
      ]
    }
  ]
}
```

サイズ見積もり: 1 run ≈ 0.7 KB（qs 20 問込み）。上限 100 件 × 3 コース ≈ 210 KB。localStorage の 5 MB に対して余裕。

### 2.3 件数の上限と間引き

- コースごとに `CAP = 100` 件。超えたら**古いものから**消す。ただし `rec: true` の run は消さない（ベストは単調に減るので件数は自然に有限）。
- 安全弁として `HARD_CAP = 200` を超えたら `rec` でも古いものから消す。
- `setItem` が `QuotaExceededError` を投げたら、`qs` を落とした縮約版で 1 回だけ再試行し、それでも駄目なら黙って諦める（既存 `store.save` と同じ「保存は便利機能」の姿勢）。

### 2.4 既存記録からの移行（`records.load()` 内で一度だけ）

`schema` が無い（= 旧形式）かつ `runs` が無いとき:

```
for each key 'tmux:<id>' in arena:
  runs.push({ id: 'legacy_<id>', course: id, ver: 1, at: date + 'T00:00:00Z',
              prefix: saved.prefix || 'C-b', time, raw: null, misses, timeouts: 0,
              keys: null, n: COURSES[id].qs.length, rank: rankFor(time/n, mul),
              rec: true, legacy: true, qs: [] })
  arena[key].ver = 1
saved.schema = 2 → 保存
```

`legacy: true` の run は一覧で「旧記録（ベストのみ）」と注記し、苦手分析からは除外（`qs` が無いので自然に除外される）。

### 2.5 `app.js` 側の変更点

1. `prepareBattle`: `b.qlog = []` を追加。
2. `loadQuestion`: `b.qlog.push({ t: type, s: null, m: 0 })` を追加（現在の問 = `b.qlog[b.i]`）。
3. `miss()`: `b.qlog[b.i].m += 1`。
4. `battleTick` の正解分岐: `b.qlog[b.i].s = +used.toFixed(2)` を `b.i += 1` の前に。
5. `timeout()`: `b.qlog[b.i].to = 1`（arena のみ）。
6. `finishBattle`（arena）: `result` を組み立てたあと `var sum = ADV.records.add(run)` に置き換え、`result` に `sum` をマージ。`arena[key]` の更新は `records.add` が担当（`result.record` の意味は変えない）。
7. `store.clear()`: `keep.runs` と `keep.schema` も残す。
8. `tmuxDa.records()` を追加（2.1 の `load()` の結果のコピーを返す）。`state().result` には `count`, `prev`, `delta` が増える。

## 3. 記録履歴: 見せ方

### 3.1 結果画面の拡張（成長を「その場で」感じさせる）

既存 `#arena-result` の `dq-log` に、`records.summarize()` の値で **1〜2 行を足す**。DQ の戦闘ログ口調で統一:

| 条件 | 文言（優先順。最大 2 行） |
|---|---|
| 新記録 かつ 2 回目以降 | 「★ 新記録！ これまでの最高より **1.4 秒** はやい」 |
| 称号が自己ベストの称号より上がった | 「称号が **戦士** から **勇者** に あがった！」（`AU.play('victory')` は既存のまま、`flash` を 1 回） |
| 前回より速い（新記録でない） | 「前回より **0.8 秒** はやくなった」 |
| 前回より遅い | 「前回より 2.1 秒 おそい。自己ベストまで あと 3.3 秒」 |
| 目標タイム達成（初回） | 「目標タイム **36 秒** を切った！」 |
| 初回 | 「はじめての挑戦。これが きみの出発点だ」 |

さらに `res-facts` の下に **ミニ推移バー（直近 10 回）** を置く。gold のバーが新記録、最新は点滅。数字は出さず「形」で見せる。その横に「通算 N 戦目」。

### 3.2 新画面「記録の間」（`#records-screen`）

名前の候補: **記録の間**（推奨。闘技場の隣の部屋という世界観）／冒険の記録／戦歴。

構成（上から）:

1. **コース切替**（タイトル画面の prefix と同じ `seg` 部品）: 草原 / 塔 / 城。記録があるコースを初期選択（優先: 直前に遊んだコース）。
2. **成長のひとこと**（見出し）: 「はじめて 42.0 秒 → いま 25.3 秒（**−16.7 秒**）」。1 件しかなければ「挑戦 1 回。もう一度走ると、ここに成長が出る」。
3. **タイル 4 枚**（`frame` 部品、モノスペース数字）: 自己ベスト / 称号 / 挑戦回数 / 直近 5 回の平均。
4. **タイム推移グラフ**: 直近 20 回の縦棒。インライン SVG、`shape-rendering: crispEdges`、棒は 4px 刻みのブロック、新記録は `--gold`、他は `--ink-dim`、自己ベストに `--teal` の点線、目標タイム par に薄い横線。棒に `<title>` で「10/20 28.4 秒 ミス 1」。ライブラリ不要（素の JS のまま）。
5. **直近の記録**（表、最大 20 行、`cheat` テーブルの見た目を流用）: 日付 / タイム / ミス・時間切れ / 称号 / ★。`legacy` 行は「旧記録」と注記。
6. **苦手な呪文**（3.3）。
7. フッター: 「闘技場へ」「タイトルに戻る」「闘技場の記録を消す」（`btn ghost`、`confirm` 付き。`records.clearArena()`）。

### 3.3 苦手分析（`records.weakness(course, 10)`）

- 対象: そのコースの直近 10 run の `qs`（`legacy` は除く）。
- 問題タイプごとに `avg = 平均秒（時間切れは limit として算入）`, `missRate = Σm / 出題回数`, `timeouts`。
- `ratio = avg / コース全体の平均秒`。`ratio` 降順、ただし出題回数 2 回以上のもの。上位 3 つを「にがてな じゅもん」、最下位 1 つを「とくいな じゅもん」。
- 表示: 呪文名（`spellsFor(Q[type])` と同じロジック: `LV.LEVELS` の `spell`）＋問題文（`Q[type].text`）＋ 平均秒 ＋ ミス率 ＋ そのキー（`LV.KEYS` の keycaps）＋ ヒント `LV.HINTS`。
- `Q` は `app.js` 内なので、`text` と `show` の参照だけ `app.js` 側で解決して描画する（`records.js` は `type` 文字列と数値だけを返す）。
- データが 2 run 未満のときはパネルごと出さない（「3 回走ると、苦手が見えてくる」と 1 行）。

### 3.4 どこから開くか

| 入口 | 表示条件 |
|---|---|
| タイトル画面 CTA の下に `#btn-records`「記録の間」（`btn ghost`） | run が 1 件以上あるとき。無ければ非表示 |
| 闘技場画面ヘッダー右に「記録の間 ›」リンク | 常時（空でも開けて「まだ記録がない」を見せる） |
| 闘技場の各コースカードの `course-best` セルを「最高 28.4 秒 ・ 12 戦」にし、クリックでそのコースの記録の間へ | run があるコースのみ。テストが見る `.course-best` の「N.N秒」テキストは保つ |
| 結果画面の CTA に「記録を見る」（「もう一度」の隣、`btn`） | 常時 |

記録の間の「戻る」は、来た場所に戻る（`S.recordsFrom = 'title' | 'arena'`）。

## 5. シェア用結果カードを邪魔しない形

- **run を自己完結した 1 オブジェクト**にする（2.2）。カードは `run` + `LV.COURSES` + `records.summarize()` だけで描ける。DOM の状態や `S.battle` に依存しない。
- 結果画面の描画を `resultModel(run) → object` と `resultHTML(model) → string` に分ける。カードは `resultModel` を再利用して別のテンプレートを当てる。
- 結果の `frame` に `data-run-id` を付ける。あとで「共有」ボタンを足すときの参照に使う。
- `run.id` を URL やカード内に載せられるよう、文字列は `[a-z0-9_]` だけにする。
- 「記録を消す」が run を消しても、カードは生成時点のデータを持つので壊れない。

## 7. テスト（`web/test/playthrough.mjs` に足すもの）

既存の `arena()` ヘルパーは「コースを 1 回走って結果を確認」まであるので、これを土台に `records(browser)` 関数を足す。`st(page)` と `localStorage` の直接シードは `persistence()` と同じ流儀。

**Step 1（MVP）**
1. 初回: `state().result.count === 1`、`result.prev === null`、`result.record === true`。
2. 「もう一度」で 2 回目を走る: `result.count === 2`、`result.prev` が数値、`result.delta === time - prev`（誤差 0.05 以内）。
3. `tmuxDa.records().runs` の各 run に `id / course / at / time / rank / qs` があり、`qs.length === n`、`qs` の各 `s` が 0 より大きいか `to: 1`。意図的ミス（既存テストの `prefix → c`）が該当問の `m` に乗っている。
4. `page.reload()` 後も `records().runs.length === 2`。
5. 旧形式の移行: `localStorage['tmux-da'] = {"arena":{"tmux:easy":{"time":30.5,"misses":1,"date":"2026-01-01"}}}` をシードして開く → `runs.length === 1`、`legacy === true`、`.course-best` に `30.5秒`。その後 easy を走り、速ければ `record === true`、ベストが更新される。遅ければ `record === false` でベストは 30.5 のまま（`fight()` の前に `page.waitForTimeout` 等で意図的に遅らせるか、シード値を `5.0` にして「遅いケース」を作る）。
6. 上限: `runs` に easy を 150 件（うち 5 件 `rec: true`、古い側に置く）シードして 1 回走る → easy の件数が 100 以下、`rec: true` の 5 件は残っている。
7. 冒険の「記録を消す」（`#btn-reset` / 最初から）を押しても `runs` が残る。

**Step 2**
8. 闘技場カードに「おすすめ」バッジが `[data-course="normal"]` にだけある。各カードに「目標 N秒」。
9. hard で全問正解しても称号が「村人」で固定にならない（`rankMul` が効いている）: `result.rank` が `RANKS` のいずれかで、`avg / 2.0` から導いた値と一致。

**Step 3**
10. タイトルの `#btn-records` は run が無いと `hidden`、あると表示。クリックで `body[data-screen="records"]`。
11. 記録の間でコース切替: `[data-rec-course="hard"]` を押すと一覧が hard の run だけになる。
12. グラフ: `#rec-chart .bar` の数が `min(20, runs.length)`、`rec` の run の棒に `.rec` クラス。
13. タイルの自己ベストが `.course-best` と同じ値。
14. 「闘技場の記録を消す」→ `confirm` を受けて `runs` と `arena` が空、カードの `.course-best` が `—`。
15. 戻る: arena から来たら arena へ、title から来たら title へ。
16. PHONE viewport で `scrollWidth <= 390`（既存の `no horizontal page scroll` と同じ検査）。
17. ページエラー・ネットワーク要求ゼロ（既存の `errors` 検査をそのまま）。

**Step 4**
18. `qs` に `copy_top` を遅く（`s: 9`）した run を 3 件シード → 「にがてな じゅもん」の先頭が サカノボリ、キー `[` が表示される。run が 1 件なら苦手パネルは出ず案内文だけ。

スクリーンショット: `SHOTS_DIR` 時に `records-<tag>` と `result2-<tag>` を追加。
